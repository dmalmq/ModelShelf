# Reviewer delivery shelf architecture

## Problem

Issue 12 adds the missing reviewer workflow above a complete Rust API. The browser must create and revisit deliveries, manage named source revisions, show async ingestion state, attach or replace revisions, finalize membership, and expose pinned run history. Rust remains the only authority for revision publication, membership replacement, locking, finalization, provenance, and error codes.

## Usage

The root route renders `ProjectShelf`. It loads projects, one selected `ProjectDetail`, and that project's `SourceModel[]`. A reviewer creates deliveries and sources there, filters sources by discipline, and opens a delivery without losing that filter.

`/deliveries/[deliveryId]` renders `DeliveryWorkspace`. It loads `DeliveryDetail` and project sources, keeps one upload attempt per source, and embeds `CombinedDeliveryViewer` unchanged. Each source row can upload a revision, retry a failed job, or attach an existing revision. A completed upload never attaches itself. The reviewer chooses the revision explicitly.

A delivery header derives draft, finalized, or run-locked presentation from the latest server response. Finalize replaces local data with the returned `DeliveryDetail`. A run row loads `RunDetail` and shows `inputProvenance` plus the exact pinned model list. Selected source, run, and discipline filter live in search parameters.

## Shape

```ts
type Remote<T> =
  | { kind: "loading" }
  | { kind: "ready"; value: T }
  | { kind: "failed"; error: ApiError };

type DeliveryLock =
  | { kind: "draft" }
  | { kind: "finalized"; finalizedAt: string }
  | { kind: "runLocked" };

type UploadAttempt =
  | { kind: "sending"; filename: string }
  | { kind: "processing"; job: IngestionJob }
  | { kind: "completed"; job: IngestionJob }
  | { kind: "failed"; job: IngestionJob };

type UploadAttempts = ReadonlyMap<string, UploadAttempt>; // sourceModelId key

interface ProjectShelfModel {
  projects: readonly Project[];
  project: ProjectDetail;
  sources: readonly SourceModel[];
}

interface DeliveryWorkspaceModel {
  detail: DeliveryDetail;
  sources: readonly SourceModel[];
  attempts: UploadAttempts;
  selectedRun: Remote<RunDetail> | null;
}
```

`DeliveryLock` is derived from `DeliveryDetail.delivery.finalizedAt`, `DeliveryDetail.locked`, and completed runs. It is never sent to Rust. Membership is derived as `sourceModelId -> modelRevisionId` from `DeliveryDetail.models`. Two MEP sources remain separate because all collections and DOM rows use source-model IDs, never discipline.

The upload attempt and current member are separate facts. A failed replacement upload therefore leaves the current ready member visible. Upload polling accepts only the job states returned by Rust. Completion refreshes `SourceModel.revisions`; it does not invent a revision from the job payload.

All external JSON enters through strict parsers in `shelf-api.ts`. Components trust parsed values. Mutations do not pre-check Rust rules or optimistically mutate membership. They replace the relevant resource with the returned response or render the returned error code and message.

## Module map

- `apps/web/src/lib/shelf-api.ts` owns shelf requests, error parsing, and strict boundary parsers. It reuses existing `fetchDelivery` and `fetchRunDetail` rather than wrapping them.
- `apps/web/src/components/shelf/project-shelf.tsx` owns project selection, delivery and source creation, the source inventory, and the delivery timeline.
- `apps/web/src/components/shelf/delivery-workspace.tsx` owns delivery/source reads, per-source upload attempts, revision attachment, finalization, selected-run loading, exact-input history, and composition of the existing viewer.
- `apps/web/src/app/page.tsx` mounts `ProjectShelf`.
- `apps/web/src/app/deliveries/[deliveryId]/page.tsx` mounts `DeliveryWorkspace`.
- `scripts/verify-ui.mjs` drives the real checker, worker, production Next build, and Chromium through the public UI.

Keep block-level render helpers in their owning component files. Extract a component only when it owns state or hides a complete repeated interaction. This avoids a directory of one-call wrappers and props-only pass-through modules.

## URL contract

- `/?project=<projectId>&discipline=<ARCH|STRUCT|MEP|OTHER>` selects the shelf project and source filter.
- `/deliveries/<deliveryId>?project=<projectId>&discipline=<value>&source=<sourceModelId>&run=<runId>` keeps the route identity in the path and preserves navigation context.
- Unknown IDs and enum values are removed after the loaded server data proves them invalid.
- Back links preserve project and discipline. Selecting a run updates `run`; selecting a source updates `source`.

## Verification contract

Use accessible names for actions and stable data attributes for server IDs and machine state. Rows expose `data-delivery-id`, `data-source-id`, `data-revision-id`, `data-job-status`, `data-run-id`, and `data-provenance`. The verifier clicks and fills the same controls a reviewer uses. It does not dispatch private React events or use a shelf window bridge.

`scripts/verify-ui.mjs --scenario deliveries` uses `scripts/lib/checker-harness.mjs`, tracked `packs/demo/fixtures/base.ifc`, `head.ifc`, `fixtures.ids`, and temporary invalid bytes. It creates two MEP sources and two deliveries through the UI, uploads and polls through the UI, keeps a ready sibling visible after one failed upload, reuses one revision, replaces another, finalizes, reloads, and compares `sourceModelId -> modelRevisionId`. The script creates a run through the API only as setup for the history-reachability criterion, then opens that run through the UI and checks complete provenance plus exact revision hashes. Evidence goes to `.omo/evidence/modelshelf-prototype/task-10/run-<timestamp>/` with screenshots, response snapshots, logs, and `results.json`.

## Synthesis decision

Candidate A is the base. It has the shortest path from page to resource owner to strict API boundary, isolates upload failures per source, and never mirrors Rust transactions.

Grafts from candidate C are the separation between a failed upload attempt and the preserved current member, plus equality checks keyed by source-model ID. The reducer, event language, epoch field, and private window driver are rejected because they add temporal decomposition and let the verifier bypass the UI.

Grafts from candidate B are explicit `data-state` attributes, clear empty and route-error states, and no automatic attachment after upload. Its nested route migration, direct server origin, and `router.refresh()` synchronization are rejected because they remount the working viewer and add a second read path.

The first reviewer judge stalled and was cancelled. The replacement read-only judge independently chose candidate A with the same grafts.

## Tradeoffs accepted

- We accept server round trips after every write in exchange for never showing membership Rust did not authorize.
- We accept bounded job polling in exchange for no new backend transport.
- We accept two state-owning client components in exchange for keeping the current same-origin API and viewer lifecycle intact.
- We accept URL-owned selection and filters in exchange for reload-safe navigation and deterministic browser verification.
- We accept explicit attachment after upload in exchange for no partial two-request operation that looks atomic.

## Alternatives rejected

- Route-owned server loaders plus mutation islands add a second data origin and remount the viewer after writes.
- One normalized reducer introduces a large event protocol for resources Rust already models and encourages private event-based tests.
- Discipline-keyed rows cannot represent two MEP sources and are invalid by construction.

## First implementation step

Add the strict shelf API boundary, then build the project shelf and delivery workspace against its parsed resource shapes before writing the verifier.
