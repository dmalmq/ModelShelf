# Snowdon Towers demo sample models

Four IFC4 discipline exports of Autodesk's "Snowdon Towers" sample building —
architecture, structure, electrical, and plumbing. Used here as the
four-discipline demo delivery, alongside the three-discipline Japanese
[BLCJ S1000 set](../blcj-s1000/README.md). The two datasets play different
roles and neither replaces the other: BLCJ is metric, near-origin, and carries
Japanese vendor property sets; Snowdon is imperial, far-from-origin, and
carries standard buildingSMART property sets.

## Why this set was added

It is the only sample data in the repository that exercises four plan
requirements at all:

| Requirement | Why only Snowdon covers it |
| --- | --- |
| Mixed model units | Every file declares `FOOT` (`lengthToMetre` 0.3048). Every other sample is metric. |
| One shared origin offset for precision | The building sits ~425 km from the world origin in survey coordinates. BLCJ sits within 20 m of it, so the requirement was never stress-tested. |
| Multiple SourceModels sharing a discipline | Electrical and plumbing are two separate MEP-family sources, with 17 GlobalIds genuinely shared between them. |
| Vendor-neutral checkable properties | Standard `Pset_WallCommon`, `Pset_BeamCommon`, `Qto_*BaseQuantities`. The BLCJ pack could only cite Rebro-specific property sets. |

## Acquisition

The repository owner exported these four IFC files himself, from Autodesk's
Snowdon Towers Revit sample projects, on 2026-08-24. They are not a
redistributed third-party download; they are a local export of Autodesk sample
content.

**A re-export will not reproduce these bytes.** Revit embeds a per-export
timestamp, a `VersionGUID`, and a `NumberOfSaves` counter in the IFC header, so
the pinned SHA-256 identifies exactly these files and cannot be regenerated by
anyone else. That is why the staging script refuses to overwrite a file whose
hash differs rather than accepting it: the recorded object counts, alignment
measurements, and any evidence derived from them belong to these exports. A
deliberate re-export means re-pinning `manifest.json` with fresh measurements,
not relaxing the check.

Export settings, read back from the file headers, that a functionally
equivalent re-export must match:

| Setting | Value | Why it matters |
| --- | --- | --- |
| Schema / MVD | IFC4, `ReferenceView_V1.2` | Determines the exported geometry representation and the available property sets. |
| Coordinate base | `Shared Coordinates` | **This is why the four models co-register.** Exporting on internal or project coordinates instead would scatter them. |
| Exchange requirement | `Architecture` for architecture, electrical, and plumbing; `Structural` for structure | MEP property sets (`Pset_PipeSegmentOccurrence`, `Pset_LightFixtureTypeCommon`) still exported correctly under the Architecture requirement, so this did no harm, but it explains the property mix. |
| Base quantities | exported | `Qto_WallBaseQuantities` and siblings are present and are candidate check targets. |
| Exporter | `Autodesk - Revit 26.4.0.32 (ENU)` via `ODA SDAI 25.12` | Revit 2026's ODA-based IFC exporter. |

Reproduce by opening the Snowdon Towers sample project in Revit 2026, exporting
each discipline to IFC4 Reference View with shared coordinates and base
quantities, then re-pinning `manifest.json`. Expect different hashes and
slightly different counts.

Stage the existing files into the working tree with:

```
node scripts/stage-snowdon-models.ts --from "<directory holding the four .ifc files>"
```

The script verifies each file against the SHA-256 pinned in
[`manifest.json`](manifest.json) and copies it to
`samples/ifc/snowdon-towers-{architecture,structure,electrical,plumbing}.ifc`
(gitignored there; see the root `.gitignore`). Re-running is a no-op when the
staged files already match.

## Usage terms

Autodesk's general terms state that, except as expressly authorized in writing,
a user will not "reproduce, modify, adapt, ... sublicense, transfer,
distribute, transmit, sell, lease, rent, loan, or otherwise make available all
or any portion of any offering to a third party". No sample-specific
redistribution grant for Snowdon Towers was found in Autodesk's published
documentation.

Consequently the `.ifc` files are treated exactly as the BLCJ archives are:
gitignored, never committed, never bundled, never redistributed. Only this
README, `manifest.json`, and `alignment.md` — provenance metadata, not the
content — are tracked in git. A teammate reproduces the files from their own
copy of the Autodesk sample content, never from git history.

If a redistribution grant is later confirmed, record the exact source and its
terms here before changing the `.gitignore`.
