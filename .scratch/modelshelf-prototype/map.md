# Build the ModelShelf prototype

Labels: wayfinder:map
Status: open
Assignee: unassigned

## Destination

A runnable local ModelShelf prototype that combines architectural, structural, and services models, checks versioned project information requirements, groups prioritized findings, and compares deliveries. Another AI can execute each child ticket from a fresh session using its prerequisites and acceptance evidence.

## Notes

- Accepted amendment: [reusable model modules](../../docs/adr/0001-reusable-model-modules.md). Shared contracts, format-neutral ObjectRefs, a reusable viewer core/React wrapper, and standalone reuse verification are required. Native Revit/Archicad integrations stay deferred.

- Execution override: the user explicitly requested tickets so another AI can build the approved plan. This map includes implementation deliverables, overriding Wayfinder's decision-only default. Charting this map does not execute the tickets.
- Use [HANDOFF.md](HANDOFF.md) as the entry point. Read [the specification](spec.md), [the starting codebase](codebase-map.md), and the chosen child ticket.
- The approved direction is Rust/Axum, local SQLite/blob storage, a separate IfcOpenShell/IfcTester worker, and Next.js. Details and boundaries remain in the linked specification and plan.
- Each child is an AFK task intended for one fresh agent context. Work one ticket per session. Ask a human only for a new product decision or inaccessible required input; record discoveries and do not silently redefine scope.
- Use poteto-mode for implementation and the installed language/frontend/testing skills as applicable. Use domain-modeling when terminology changes. The current task used Wayfinder and to-tickets to chart the work.
- First implement and verify Wave 1. The Wave 1 review-loop ticket is the milestone boundary. Wave 2 completes the rest of the approved prototype; do not claim it finished after the first milestone.
- Tickets were initially created open and unassigned; current child metadata is authoritative. Partial code is context, not evidence of completion. The started worker contract/dependencies need implementation and validation.
- Native issue blocking is unavailable in the local tracker. Child metadata records blockers; the read-only check-tickets.mjs command derives the current frontier.
- No external issues were published. No commits, pushes, PRs, deployment, or public sample redistribution are authorized here.

Unblocks tickets 02, 03, and 07. No caller wired in yet (out of this ticket's scope).
- [Inspect IFC through a verified worker contract](issues/03-ifc-worker-contract.md) — resolved: implemented `services/ifc-worker` (`operation: inspect` only) per `docs/contracts/worker-v1.md`, verified against the real restricted sample (127 objects, hashes/counts independently checked, both `absent`/`available`/`unsupported` geometry states and length/area/volume SI normalization exercised). Added `ObjectRecord.ref: model_contracts.ObjectRef` as a `worker-v1.md` contract addition (the shared occurrence ID predates that doc). `operation: validate` is explicitly rejected as not-yet-implemented, left for ticket 06. Also curated `services/ifc-worker/pyproject.toml`'s previously-unconfigured `ruff`/`basedpyright` strictness presets down to something this codebase can actually satisfy (0 findings either way now).
- [Create deliveries from immutable source-model revisions](issues/02-immutable-deliveries.md) — resolved: added `source_models`/`model_revisions`/`delivery_members` + `deliveries.finalized_at` via a proper versioned, transactional, fault-tested migration runner (`services/checker/src/db.rs` + `migrate_v2.rs`); new endpoints for source models/revisions/membership/finalize. Verified live via `scripts/verify-api.mjs --scenario revisions`: two same-discipline sources in one delivery, revision reuse without re-upload, finalize immutability under 20-way concurrent contention. Found and fixed two real bugs along the way: `crates/model-contracts` was missing `express_id_to_object_id` (added, now 3-language-tested) and `objects.model_id`'s foreign key still pointed at the frozen `models` table (rebuilt, with FK enforcement off for the whole transaction and an explicit `pragma_foreign_key_check` gate before commit). Unblocks ticket 04 (now only blocked by nothing — both its prerequisites, 02 and 03, are resolved).
- [Process model revisions through durable jobs](issues/04-queued-ingestion.md) — resolved: `POST /api/source-models/:id/revisions` now enqueues an `ingestion_jobs` row and returns `202` immediately; a single background worker (`services/checker/src/jobs.rs`) invokes the real `ifc-worker` out of process, validates its entire protocol (schema version, job identity, exit code, manifest/artifact hashes and paths, the shared occurrence-id contract) before publishing anything, and marks a job `failed` (never a false success or a hang) on any violation. A job interrupted by a crash is recovered as `failed` on restart; retries are idempotent. Verified via `scripts/verify-api.mjs --scenario worker-failure` (new): 7 real-subprocess failure modes each leave the job failed with nothing published, concurrency never exceeds one running job, and restart+retry recovers via the real worker. `--scenario revisions` reworked for the async contract and still passes. Viewer-facing object/property extraction now comes from the worker, not a second Rust parse; `fp_*` diff hashes (which the worker cannot supply) still come from `ifc_model`+`fingerprint`, untouched. A concurrent session added `MIGRATION_0004`/run-input-provenance while this was in flight; rebuilt/retested after it landed, no conflict (disjoint tables).
- [Prepare reproducible Japanese and synthetic demo evidence](issues/05-demo-evidence.md) — resolved: acquired the real BLCJ S1000 architecture/structure/MEP IFC exports via a checksum-pinned, idempotent `scripts/fetch-demo-models.mjs`; documented (with real bounding-box/grid/storey evidence) that the three already share one coordinate frame, no transform needed. Authored 11 IDS checks in a v1/v2 pack (one explained rule change) entirely from properties actually found by inspecting the real files, cross-referenced against `references/bim-checking`'s Sankai/MLIT/BLCJ sources — full traceability in `packs/demo/checks.md`. Built a self-authored synthetic A/B fixture pair (`scripts/generate-demo-fixtures.py`) plus a verified machine-readable oracle covering repeated failures, additions/removals, property/shape/move/rotation changes, and ambiguous GlobalIds. Found and fixed a real, previously-undiscovered bug along the way: `crates/modeldiff/src/heuristic.rs`'s placement-origin indexing didn't match `ifc_model::Transform::to_array12`'s actual layout, silently missing real moves and misreporting pure rotations as moves — invisible to the crate's own unit tests because their hand-built fixtures matched the same wrong convention. Fixed as a prerequisite; all pre-existing `modeldiff` tests still pass. Added two new, reusable dev tools (`cargo run -p ids --example evaluate_pack`, `cargo run -p modeldiff --example diff_fixtures`) for running a pack or diff directly against real IFC files with no service involved.

## Not yet specified

None is too vague to ticket at this stage. The viewer ticket and Wave 1 gate measure compatibility/performance and carry an explicit prepared-geometry fallback. Any new implementation fact that changes the destination must be recorded in the owning ticket and brought back to the user.

## Out of scope

Regulatory approval, clash/fire-code geometry checking, Revit write-back, arbitrary spreadsheet conversion, production authentication/billing, automatic acceptance of ambiguous object matches, and unrestricted third-party asset redistribution.
